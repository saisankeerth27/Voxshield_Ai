# VoiceShield — Demo Guide

A 2–3 minute walkthrough for showcasing VoiceShield at a hackathon demo.
Everything below uses the real ML models already bundled with the project —
no results are faked.

> **Quick start (recommended for this machine):** use the SQLite demo setup.
> PostgreSQL is optional; see [Database setup](#database-setup).

## 1. Start the backend

From the repository root:

```bash
cd backend
# (PowerShell) create/use the virtualenv and install once
python -m venv venv
venv\Scripts\activate
pip install -r requirements.txt

# Run with SQLite (no external database needed)
$env:DATABASE_URL = "sqlite:///./voiceshield_demo.db"
venv\Scripts\python.exe -m uvicorn app.main:app --host 0.0.0.0 --port 8000
```

On first lightweight use the ML models load on demand (Wav2Vec2 for deepfake
detection, ECAPA-TDNN for speaker verification). Model files are cached under
`backend/models/` after the first run.

Verify: open `http://localhost:8000/health` → `{"status": "healthy"}`.

## 2. Start the frontend

In a second terminal:

```bash
cd frontend
npm install
npm run dev
```

Open `http://localhost:5173`. The "Backend online" badge on the landing page
confirms connectivity.

## 3. Demo sequence (~2–3 minutes)

1. **Landing page** — title "AI-Powered Voice Cloning & Impersonation Attack
   Detection", two CTAs, the 1-2-3 pipeline explanation.
2. **Analyze a synthetic sample (HIGH risk showcase)**
   - Analyze → **Upload** tab → choose `demo/audio/synthetic_tts.wav`.
   - Click **Analyze Voice** — watch the live checklist:
     Audio uploaded → prepared → AI voice detection → speaker verification
     → risk calculation → **Analysis completed**.
   - Result: AI-generated probability high, **Risk: HIGH**, and the
     "Recommended action".
3. **Create a reference profile**
   - Speaker Profile → speaker name → upload `demo/audio/genuine_human.wav`
   - → **Create Profile** → "Profile Created Successfully".
4. **Re-analyze with speaker verification (optional)**
   - Re-run **Analyze Voice** on the same upload, or analyze a fresh human
     sample, to see speaker similarity and a full risk verdict.
5. **Record from microphone (optional)**
   - Analyze → **Record** tab → Start → Stop → playback → **Analyze Voice**.
   - The mic input is processed locally and uploaded only when you commit.
6. **Dashboard & History**
   - Dashboard shows the latest analysis summary; History lists date, source,
     audio, AI detection, speaker match, risk badge, and status.
   - Click **View** on a row to open the full analysis detail + report
     download.

## 4. Database setup

- **SQLite (default for demo):** nothing to install. Set
  `DATABASE_URL=sqlite:///./voiceshield_demo.db`. Data persists in that file;
  delete it to reset the demo.
- **PostgreSQL (optional):** create a database and run the backend with
  `DATABASE_URL=postgresql+psycopg://<user>:<pass>@localhost:5432/voiceshield`.
  The app creates tables automatically on startup.

## 5. Troubleshooting

| Symptom | Fix |
| --- | --- |
| "Unable to connect to the backend" on a page | Start uvicorn; check `http://localhost:8000/health` |
| Upload rejected | Use `.wav/.mp3/.m4a/.ogg/.webm`, ≤ 25 MB; ffmpeg must be installed for format conversion (`imageio_ffmpeg` fallback is used if ffmpeg is missing) |
| Slow first analysis | The first deepfake/speaker model load downloads/inits models; subsequent runs are faster |
| Models fail to download | No internet? Use `backend/pip install -r requirements.txt` offline bundles, or pre-place model files under `backend/models/` |
| Ports busy | Change uvicorn `--port` and set `VITE_API_BASE_URL` in `frontend/.env` to match |

## 6. Honesty notes for the demo

- The risk score is an in-house heuristic (0–1), not a published metric —
  the UI labels it as an estimate.
- Sample audio in `demo/audio/` is bundled for convenience and labeled
  honestly in `demo/README.md`; it is not generated by VoiceShield.
- A missing speaker profile means verification is "unavailable", risk is
  built from the AI-detection signal alone, and the UI says so explicitly.
