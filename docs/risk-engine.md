# VoiceShield Risk Fusion Engine

> **Status:** MVP heuristic implementation (Phase 6).
> **This risk score is NOT a scientifically validated probability of attack.**
> The weights and thresholds below are configurable defaults and must be
> calibrated on representative, labelled validation data before any
> security-critical deployment.

## 1. Overview

The risk fusion engine combines two independent analysis signals into a
single, deterministic, explainable risk assessment:

| Signal | Source | Stored in DB | Raw range |
|---|---|---|---|
| AI-generated probability | Wav2Vec2 deepfake detector (Phase 4) | `ai_probability` | [0, 1] |
| Speaker cosine similarity | ECAPA-TDNN speaker verification (Phase 5) | `speaker_similarity` | [-1, 1] |

Both values are read from the database — the client never supplies them.

## 2. Risk Formula

```
similarity_risk  = (speaker_similarity + 1) / 2          # [-1,1] → [0,1]
impersonation    = ai_probability × similarity_risk
risk_score       = DEEPFAKE_WEIGHT × ai_probability
                 + SPEAKER_WEIGHT  × impersonation
```

Clamped to [0, 1] and stored rounded to 6 decimal places.

### Why gated (not averaged)

A cloned voice produces **high AI probability + high similarity**.
A genuine recording can also produce high similarity (same speaker).
High similarity **alone** is not suspicious — it means the speaker matches
the reference. The impersonation component is gated by the AI probability
so that high similarity cannot create high risk without synthetic-speech
evidence.

### Similarity mapping detail

| Cosine similarity | similarity_risk | Interpretation |
|---|---|---|
| -1.0 | 0.0 | Very dissimilar — no impersonation signal |
| 0.0 | 0.5 | Neutral — identity unclear, intermediate contribution |
| +1.0 | 1.0 | Identical voiceprint — maximum impersonation signal |

This transformation is explicit, linear, and documented here.

## 3. Default Weights and Thresholds

All configurable via environment variables.

| Parameter | Env var | Default | Constraints |
|---|---|---|---|
| Deepfake weight | `DEEPFAKE_WEIGHT` | 0.60 | Must sum to 1.0 with speaker weight |
| Speaker weight | `SPEAKER_WEIGHT` | 0.40 | Must sum to 1.0 with deepfake weight |
| Low max (inclusive) | `RISK_LOW_MAX` | 0.39 | 0 ≤ low_max < medium_max ≤ 1 |
| Medium max (inclusive) | `RISK_MEDIUM_MAX` | 0.69 | 0 ≤ low_max < medium_max ≤ 1 |
| Similarity "high" threshold | `SPEAKER_SIMILARITY_HIGH` | 0.50 | For explanation wording only |
| Engine version tag | `RISK_ENGINE_VERSION` | 1.0 | Stored with each assessment |

Startup validation (pydantic model_validator) rejects invalid weight sums
and threshold ordering before the server starts.

## 4. Risk Levels

| Level | Score range | Colour |
|---|---|---|
| LOW | [0.0, 0.39] | Green |
| MEDIUM | (0.39, 0.69] | Amber |
| HIGH | (0.69, 1.0] | Red |

Boundary: LOW_MAX is inclusive for LOW, MEDIUM_MAX is inclusive for MEDIUM.

## 5. Incomplete / Missing Data

If **either** `ai_probability` or `speaker_similarity` is `None`:

- Status: `INCOMPLETE`
- No risk score or level is produced
- Explanation names the missing signal(s): "deepfake detection" and/or
  "speaker verification"
- Recommendation: "Complete deepfake detection and speaker verification
  before calculating risk."

There is **no partial-risk mode** — both signals are required.

## 6. Explanation and Recommendation Logic

Explanations are generated by the engine based on the risk level and the
normalised signal strengths. They are deterministic for the same inputs.

**LOW:** Both signals low; no evidence of synthetic speech or impersonation.

**MEDIUM — moderate AI + moderate/high similarity:**
Suggests additional identity verification.

**MEDIUM — moderate AI, low similarity:**
Synthetic concern exists but impersonation evidence is weak.

**HIGH — high similarity (≥ 0.5 risk):**
High synthetic-speech probability + strong voiceprint match — possible
impersonation. Recommends independent identity verification.

**HIGH — low similarity (< 0.5 risk):**
High synthetic-speech probability present, but impersonation evidence is
weaker; synthetic audio may be present.

## 7. API Endpoints

### `POST /analysis/{analysis_id}/risk`

Calculate risk from the stored deepfake + speaker results.

- **Client sends:** only `analysis_id` (no body needed, JSON body is ignored)
- **Server reads:** `ai_probability`, `speaker_similarity` from database
- **Idempotent:** if `risk_status == CALCULATED` and `risk_score` exists,
  returns the stored result without recomputation
- **400** `incomplete_analysis`: missing one or both required signals
- **404** `not_found`: analysis does not exist
- **200** on success with `RiskCalculateResponse`

### `GET /analysis/{analysis_id}/risk`

Return the stored risk result without recomputation.

- **200** with `RiskResultResponse` (risk fields may be `null` if not yet
  calculated)
- **404** if the analysis does not exist

### `GET /audio/{analysis_id}` and `GET /audio`

Both include risk fields (`risk_status`, `risk_score`, `risk_level`,
`risk_explanation`, `risk_recommendation`, `risk_processing_time`,
`risk_engine_version`) when populated.

| Column | Type | Notes |
|---|---|---|
| `risk_status` | String(20) | `PENDING / PROCESSING / CALCULATED / FAILED` |
| `risk_score` | Float | 0.0–1.0, 6 dp |
| `risk_level` | String(10) | `LOW / MEDIUM / HIGH` |
| `risk_explanation` | String(2000) | Human-readable explanation |
| `risk_recommendation` | String(2000) | Action recommendation |
| `risk_processing_time` | Float | Seconds |
| `risk_engine_version` | String(20) | Version tag stored at calculation time |

New enum values added:
- `AudioAnalysisStatus`: `RISK_CALCULATED`
- `RiskStatus`: `PENDING, PROCESSING, CALCULATED, FAILED`
- `RiskLevel`: `LOW, MEDIUM, HIGH`

Column types use plain `String`/`Float` (not PG enums) for SQLite
`create_all` consistency, matching the Phase 5 `speaker_verification_status`
pattern.

## 11. Limitations and Calibration Requirements

- **Not a validated probability of attack.** The score is a heuristic.
  It should NOT be used as the sole decision criterion for security-sensitive
  actions.
- **Single-speaker scope.** The risk engine assumes one registered reference
  speaker. Multi-speaker scenarios require a different architecture.
- **No temporal context.** Each analysis is evaluated in isolation; there is
  no session or multi-sample aggregation.
- **Calibrated on what data?** The default thresholds (0.39/0.69) are
  reasonable starting points but must be validated against a representative
  dataset of real and synthetic samples before deployment.
- **Similarity threshold independence.** The speaker verification threshold
  (0.25) and the risk engine similarity threshold (0.50 for explanation
  wording) are separate parameters and should be tuned independently.
- **No alerts or WebSocket in this phase.** Real-time risk notifications
  are deferred to Phase 7+.
- **Cosine similarity [0,1] transformation** is a simple linear map. A
  non-linear mapping may be more appropriate after empirical evaluation.

## 12. Phase 7 Readiness

The risk engine provides a stable, modular foundation for:

- **Alerts / notifications** (email, webhook, in-app) triggered on HIGH risk
- **WebSocket streaming** for real-time risk status on the frontend
- **Risk history dashboard** with time-series visualisation
- **Configurable risk thresholds per user / organisation**
- **Multi-sample risk aggregation** (session-level risk scoring)
- **Audit logging** of all risk calculations for compliance
